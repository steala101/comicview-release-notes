# v2.2.3

## 漫画ライブラリの検索

- 整理済み作品の登録題名が略称の場合も、保存フォルダーに含まれる正式名や巻範囲で検索できるようにしました。

## 読書・AI高画質化

- 低解像度の巻でAI補正の確認をキャンセルしても、ライブラリに戻って同じ巻を開き直すと再判定し、条件に合う場合は確認を表示します。読んでいる間は同じ確認を繰り返しません。以前にキャンセルした記録も次回の確認を妨げません。
- 巻を開き直す時はスクロール表示の画像も読み直し、元画像の解像度を基準に判定します。短時間で巻を閉じて開き直した場合も、前回の判定結果が現在の確認へ干渉しないようにしました。

## リンク取得・自動整理

- 複数タイトルのリンク登録・ダウンロード中も、完了したタイトルの監視を進められるようにしました。JDownloaderのリンク収集や移動を待つ間は共有ロックを解放し、残りの取得と自動整理を並行して進めます。
- 新規タイトルは、完了書庫の確認・作業コピーの準備後、VPNの完了記録やJDownloaderの一覧の後片付けを待たずに整理を開始します。VPNは残りのダウンロードに必要な間は維持し、一覧削除の前には完了IDを記録します。整理処理と確認画面は従来どおり一作品ずつ進めます。
- VPN使用中の複数タイトル監視で、取得リンクごとに登録履歴全体を読み直していた処理を、一巡で一度の読込に変更しました。VPNの進捗通知も複数作品分をまとめて保存し、漫画の閲覧と競合する履歴処理の負荷を減らしました。
- 進捗表示と新規整理待ち一覧は同じ履歴を再利用します。NordVPNの接続先一覧も変更がない間は解析結果を再利用し、接続先や一覧ファイルが変わった場合は再判定します。VPNの保護設定・対象アプリ・LAN経路は変更しません。
- 登録履歴が大きくなっても、一作品の参照・状態更新で過去の全作品を繰り返し解析・整形しないようにしました。登録、ダウンロード開始、自動整理、進捗表示が履歴処理で待たされる時間を減らします。既存のJSON履歴はそのまま利用でき、外部更新・中止・保存失敗の検査も維持します。
- 作品の巻一覧取得をサイト一覧・検索とは別の待ち列に分け、異なるページの通信を共通ロックで待たせないようにしました。同じページへの重複取得はまとめ、サムネイル表示も通信待ちから切り離します。稼働中のVPN監視の確認も、VPN操作の終了を待たずに戻るようにしました。
- ダウンロード中の作品は完了状態の監視を先に行い、蔵書との詳しい照合はダウンロード・解凍完了後に行います。完了した作品を未完了作品や一覧の後片付けより優先して整理し、VPN中でも実際に整理中・確認待ちならその状態を表示します。整理と確認画面は一作品ずつ進めます。
- 蔵書との作品照合では、変更のない題名・副題・明示された別名の解析結果を上限付きで再利用します。作品名・保存場所・媒体が変われば別の条件で判定し、取得計画や巻一覧の再表示を軽くしました。
- 「接続・保存先設定」で、MyJDownloaderに接続してWindows版・Docker版それぞれのデバイスを選べます。保存済みの認証を共用し、デバイス一覧の更新・オンライン表示・接続テストに対応しました。Docker版の保存先はWindows側が `D:\T\保存フォルダ新`、コンテナ側が `/output` です。Docker版のVPN接続・再接続・Kill SwitchはGluetunが管理し、VPNの事業者や通信方式を変えてもComicViewの設定は共通です。JD2の接続テストが成功しても、VPN状態は未確認と表示します。
- Docker版を選択している間は、このPCのWindows版NordVPNへの接続・切断操作を保留します。切替前のWindows版ジョブの確認は登録元で続け、必要なVPN解除はWindows版へ戻ってから確認します。
- Docker版JD2へのMyJDownloader通信でHTTPS接続を再利用し、リンクグラバーへの登録と自動ダウンロード開始にかかる確認時間を短縮しました。
- 設定で取得先を切り替えても、既存のダウンロードの確認・中止・整理後の一覧削除には登録元のデバイスを使います。旧Dockerローカル接続の履歴は登録元を確定できないため、JD2側で確認してください。
- JD2の登録処理を途中から記録し、照合に失敗した場合も、登録時の目印や確認済みIDで今回のリンクを見つけて中止できるようにしました。別のJD2で同じ保存先を使用中の登録や、結果が不明な登録の重複を防ぎます。
- 完了した作品の整理開始を早め、VPNが継続中でも整理済みの作品は完了と表示します。対象リンクの削除後に空パッケージが残った場合も、空であることを確認できれば整理完了として扱います。
